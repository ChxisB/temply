A

淨係撳掣：▲▼ 移，+ sheet 加

唔靠任何手勢。選中一個 block，動作列有 ▲▼，一撳移一格；+ 永遠插喺選中 block 下面（冇選中就加喺最尾）。

好處

  • 零學習成本，唔會誤觸
  • 同 scroll 冇衝突（手機拖放最大死穴係同滾動打交）
  • 實作最穩

代價

  • 移遠距離要撳好多下
  • 唔夠「app 感」
B

手勢為主：長按拖，block 之間 + 線

每個 block 左邊有 handle，長按 0.3 秒拎起（震一下），拖到位放手。Block 之間永遠有一條幼 + 線，撳邊條就喺邊度插。

好處

  • 最直觀、最似原生 app
  • 插入位置一撳即中

代價

  • 長按同 iOS 文字選取、同 scroll 三者打交，要好多調校
  • 拖去螢幕外要 auto-scroll，難做得順
  • 每個 block 之間一條線，canvas 變得好嘈
C

兩樣都有，撳掣先行（建議）

A 嘅 ▲▼ 同 + sheet 係基礎，一定做。加上：選中咗 block 先出現 handle（可以長按拖）同佢下面嗰一條 + 線 —— 唔係每個 block 都有線，所以唔嘈。拖放做第二階段，第一階段冇佢都用得。

好處

  • 第一階段就過到驗收（用 ▲▼）
  • 拖放係加分，做得唔好都唔影響基本操作
  • 「選中先出現」令 canvas 平時乾淨

代價

  • 兩套路徑要維護
  • 拖放嘅調校成本最終都要付

三個都假設：撳一下 block 就係選中（出動作列），撳文字入面第二下先入文字編輯；撳空白位取消選中。
