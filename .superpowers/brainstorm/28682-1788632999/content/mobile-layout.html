A

Canvas 為主，其他嘢用 bottom sheet（建議）

Canvas 填滿螢幕，同 Google Docs app 一樣。底部一條五格 bar：Content 係 canvas 本身，Details／Brand／Data／Checks 各自由底部彈上一個 sheet，改完拉低就返 canvas，唔會離開 email。右下角 + 開「加 block」sheet。選中 block 時底部出現該 block 嘅動作列；打字時同一位置變成文字格式列，貼住鍵盤。頂部 bar 得三樣：返回、subject、Preview 眼仔同 Publish。

好處

  • 成日見到 email 本身，改嘢即刻見到效果
  • 底部所有嘢一隻手拇指到得
  • Sheet 可以摺高摺低，大 sheet（Brand advanced、Data）都容得落
  • HTML／Text source 放喺 Preview 眼仔嘅 sheet 入面，一樣做到 100% 對等

代價

  • 同桌面版結構唔同，要新寫一個手機殼（sandbox 要拆開 canvas 同周邊）
  • Sheet 嘅高度、鍵盤、滾動要好仔細調
B

保留卡片直落，執靚佢

結構同桌面一樣，但 Details 同 Brand 預設摺埋、頂部 toolbar 縮做 Publish + ⋯、canvas 加觸控動作列。改動最細。

好處

  • 改動最少，桌面同手機一套 code
  • 用戶由桌面轉手機唔使重新學

代價

  • 仍然係長 scroll：改 brand 顏色要滾上去、睇效果要滾落嚟
  • Canvas 永遠只佔螢幕一部分，鍵盤一彈出剩返一半
  • 「唔上手」嘅根源（桌面結構搬落手機）冇解決
C

頂部 tab 分四頁

Details、Brand、Content、Preview 四個 tab，各佔全屏。Content tab 就係 A 嘅 canvas 同動作列。

好處

  • 每頁專注一件事，結構一睇就明
  • 比 A 少一層（冇 sheet）

代價

  • 改 brand 顏色要切去 Brand tab，睇效果又切返 Content，來回切換
  • Preview 係另一個 tab，同 edit 分開，冇得「一路改一路睇」
  • Data 同 Checks 冇位，要塞入 Content 嘅 ⋯ 入面

三個都假設：桌面（≥ 640）維持而家嘅 layout；觸控裝置（`pointer: coarse`）無論闊度都用底部動作列同觸控拖放。
